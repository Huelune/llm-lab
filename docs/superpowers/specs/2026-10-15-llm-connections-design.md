# LLM 연결 설정 페이지와 프로젝트 이름 설계

- 작성일: 2026-10-15
- 상태: 구현됨 (2026-10-15)

## 1. 배경과 목표

지금 `llm-fix-server`는 켤 때 `.env`(또는 `.env.이름`)에서 LLM 연결 하나를 읽어 끝까지 쓴다. 다른 모델이나
게이트웨이를 쓰려면 파일을 고치고 서버를 다시 켜야 하고, 화면에서는 지금 무엇에 연결됐는지 알 수 없다.

목표:
- 웹 설정 페이지에서 LLM 연결을 **추가·수정·삭제**하고, 그중 하나를 **현재 연결로 선택**한다.
- 모든 화면 위쪽 막대에 현재 연결 이름을 보인다.
- 프로젝트 이름을 **LLM Test Advisor**로 바꾸고, 첫 화면 맨 위에 이름과 한 줄 설명을 보인다.

### 범위

포함: 연결 목록 저장, 설정 페이지(목록·추가·수정·삭제·선택·연결 확인), 작업에 쓴 연결 기록, worker가 작업의
연결로 요청하기, `.env` 연결 자동 등록, 이름과 첫 화면 제목.

제외: 분석마다 연결 고르기, 로그인·여러 사용자, 키 암호화, `llm-probe`의 연결 고르기. 서버는 지금처럼
`127.0.0.1`에서만 열린다.

## 2. 이름

- `APP_NAME`(위쪽 막대, 브라우저 탭 제목): `LLM Test Advisor`.
- 첫 화면 맨 위: 큰 제목 `LLM Test Advisor`, 그 아래 한 줄 설명
  "정적 분석 결과와 소스 코드를 묶어 LLM에 묻고, 판단과 수정안을 받습니다." 그 아래가 지금의 "새 분석" 양식이다.
- README 첫 줄과 서버 시작 안내 문구의 이름도 바꾼다. 패키지·명령 이름(`llm-fix-server` 등)은 그대로 둔다.

## 3. 연결

### 3.1 연결 하나의 값

이름(사용자가 붙임, 목록 안에서 하나뿐), 접속 방식(`openai` / `azure`), 주소, 키, 모델, 선택 값(프로젝트 ID,
프로젝트 헤더 이름, API 버전, 요청 타임아웃, SSL 검증, thinking). 지금 `Settings`의 연결 관련 칸과 같고,
검사 규칙(주소·모델 필수, azure면 키 필수, 타임아웃은 양수 등)도 `settings_from_env`와 같다.

서버 전체 설정인 `LLM_WORKERS`, `LLM_FOLLOW_UPS`는 연결에 넣지 않고 `.env`에 둔다.

### 3.2 저장

- 파일: 데이터 폴더(`private/`, `--profile`이면 `private/이름/`)의 `connections.json`.
  `{"current": "이름", "connections": [{...}, ...]}`. git에 올라가지 않는 폴더이고, `.env`처럼 이 PC에만 있다.
- 쓸 때는 임시 파일에 쓰고 바꿔 넣어 깨진 파일이 남지 않게 한다. 읽다 실패하면(깨진 JSON) 서버는 켜지되 설정
  페이지에 "연결 설정 파일을 읽지 못했습니다(종류)"를 보인다.

### 3.3 `.env` 연결

서버를 켤 때 `.env`(프로필이면 `.env.이름`)에 연결 설정이 있으면 이름 `.env`인 연결로 목록 맨 앞에 넣는다.
이 연결은 읽기 전용이다(설정 페이지에서 고치거나 지울 수 없고, 파일을 고친 뒤 서버를 다시 켠다). 저장된
현재 연결이 없으면 `.env` 연결이 현재 연결이다. 그래서 지금 쓰는 방식이 그대로 동작한다.

`.env`가 없거나 연결 값이 비어 있어도 서버는 켜진다(지금은 설정 오류로 멈춘다). 연결이 하나도 없으면 첫 화면에
"설정에서 LLM 연결을 추가하세요"(설정 페이지 링크)를 보이고 "분석 시작"을 막는다. `.env` 값이 잘못됐으면(예:
타임아웃이 숫자가 아님) 지금처럼 설정 오류로 알리고 멈춘다.

### 3.4 설정 페이지 `/settings`

- 목록: 연결마다 이름, 접속 방식, 모델, 주소, 현재 연결 표시, 버튼(현재 연결로 선택 / 수정 / 삭제 / 연결 확인).
  `.env` 연결은 수정·삭제 버튼 없이 "`.env` 파일에서 고침"을 보인다.
- 추가·수정 양식: 위 값들. 키 칸은 `type="password"`이고 저장된 키를 다시 채우지 않는다. 수정 때 키 칸을 비우면
  저장된 키를 그대로 쓴다. 저장 전에 3.1의 규칙으로 검사하고, 틀리면 양식에 이유를 보인다.
- 삭제: 확인을 거친다. 현재 연결은 지울 수 없다(먼저 다른 연결을 선택).
- 연결 확인: 그 연결로 짧은 chat 요청을 하나 보내고, 결과를 성공 / 인증 실패(401·403) / 주소·모델 오류(404) /
  연결 실패 / 그 밖으로 보인다. 판정은 `probe.classify_error`를 쓴다. 오류 원문은 보이지 않는다.
- 키는 어떤 페이지 HTML에도 나오지 않는다.

### 3.5 위쪽 막대

모든 페이지 위쪽 막대 오른쪽에 "연결: 이름"(설정 페이지 링크)을 보인다. 연결이 없으면 "연결: 없음". 모델 이름은
막대에 넣지 않는다(화면 캡처에 남지 않게. 설정 페이지에만 있다). 캡처용 요약 페이지(`/results/N/summary`)에는
연결 이름도 넣지 않는다.

## 4. 작업과 연결

- 작업을 만들 때 현재 연결의 이름을 작업에 기록한다(`jobs.connection`, 새 칸. 예전 작업은 빈 값 = `.env` 또는
  그때의 현재 연결).
- worker는 묶음을 처리할 때 작업의 연결로 클라이언트와 모델을 정한다. 연결 이름별로 클라이언트를 만들어 두고,
  연결이 수정되면 다시 만든다.
- 처리 중에 현재 연결을 바꿔도 그 작업은 기록된 연결로 끝까지 간다. 그 연결이 지워졌으면 작업을 멈추고
  "작업의 LLM 연결이 없어졌습니다. 설정에서 연결을 고른 뒤 다시 시도하세요"를 보인다. 예전 작업(빈 값)은
  현재 연결을 쓴다.
- 작업 화면 부제에 쓴 연결 이름을 보인다.
- 저장된 답 재사용 키는 지금처럼 모델 이름을 포함하므로, 모델이 다른 연결끼리 답이 섞이지 않는다.
- 대화 기록은 지금처럼 모델과 보낸 주소를 남긴다.

## 5. 오류 처리

- 설정 파일 읽기·쓰기 실패: 종류와 할 일만 보인다(경로·원문 없음).
- 같은 이름으로 추가: 양식에 "같은 이름의 연결이 있습니다".
- 연결 확인 중 시간 초과: "연결 실패(시간 초과)".

## 6. 테스트

- 연결 저장소: 추가·수정(키 비우면 유지)·삭제·선택, 현재 연결 삭제 거절, 같은 이름 거절, 깨진 파일 읽기,
  `.env` 연결 자동 등록과 읽기 전용.
- 설정 페이지: 목록·양식 HTML에 키가 없음(`secret` 키 값으로 확인), 검사 오류 표시, 연결 확인 결과 종류(가짜 서버).
- 위쪽 막대에 현재 연결 이름, 요약 페이지에는 없음, 연결이 없을 때 분석 시작 막힘.
- worker: 작업이 기록된 연결로 요청함(두 가짜 서버), 처리 중 현재 연결을 바꿔도 그대로, 지워진 연결이면 작업 멈춤.
- 이름: 위쪽 막대·탭 제목·첫 화면 제목.
